# 图片摘要生成设计

## 背景

规范文档里的关键信息常常**只以像素形式存在**：证照、扫描件、签章、表格截图、
现场照片。它们的文字提取不出来（本身就是图片），于是：

- 切块文本里只有 `![](images/image5.jpg)` 一行引用；
- 检索问"珠海南方软件园的产权证"时**永远命中不了**那张图；
- 图里的权属人、编号、日期、金额这些最有价值的信息，等于不存在。

本功能让多模态模型把图"读出来"，写成一段描述回填到 markdown，从而**参与切块与
检索**——让图里的内容第一次变得可搜索。

## 一、总体流程

```
解析弹窗勾选「生成图片摘要」（默认关闭）
   ↓
前端预检 ── 不可用 → 弹窗："图片摘要需要管理员先配置「图片解析模型」，请联系系统管理员"
   ↓ 可用
后端校验（兜底，防 API 直调绕过前端预检）
   ↓
解析（含盖章合成，见 stamp.py）
   ↓
逐张生成摘要 ← 本功能新增
   ├ 跳过：面积过小的图（印章类）
   ├ 跳过：超出张数上限的图
   └ 单张失败 → 跳过 + 记一笔，不阻塞
   ↓
回填 markdown（图片下方，引用块）
   ↓
切块（「图 + 摘要」作为不可切分区间）→ 入库
```

**摘要必须在切块之前**：只有进了 markdown，才会被切进 chunk 文本、才可能被检索到。
切块之后再生成摘要，就只剩展示价值了。

## 二、三层配置

| 层 | 谁配 | 配什么 | 位置 |
|---|---|---|---|
| **模型列表** | 超管 | 多个多模态模型（名称 / 地址 / 密钥 / 模型名），**第一个为默认** | 系统配置页 → 「图片解析模型」卡片 |
| **选模型 + 提示词** | 部门管理员 | 从列表选一个 + 结构化选项 + 可微调 prompt | 部门配置页 → 「图片摘要」段 |
| **是否启用** | 解析操作者 | 解析弹窗勾选，默认关闭 | 文档列表 → 解析弹窗 |

- 部门没配 → 用超管的**第一个模型** + 全局默认提示词，不报错
- 超管删掉了某部门选中的模型 → 该部门回退到第一个，部门配置页给出提示
- 模型的连接信息**只有超管能配**（与 MinerU / DeepDoc 一致：解析能力归超管）

## 三、提示词设计

### 结构化选项 → 自动生成 → 可微调

每个勾选项对应一段固定措辞，勾选后拼成完整 prompt；生成后可手动微调，改过则标记
「已自定义」，并提供「恢复默认」。

| 选项 | 拼进 prompt 的措辞 | 默认 |
|---|---|---|
| 标注文件类型 | `类型：这是什么（文件类型或场景）` | ☑ |
| 读出图中文字 | `文字：图中可见的关键文字（标题、单位名称、编号、日期、金额、规格等）` | ☑ |
| 描述主体与场景 | `画面：画面主要对象与特征（设备、场地、人物、签章等）` | ☑ |
| 描述布局与结构 | `版式：版式结构（表格行列、签章位置、分区布局等）` | ☐ |

**结尾的固定约束不随选项变、不允许部门改**：

```
要求：
- 只描述你确实看到的内容，不要推测、不要评价、不要补充常识
- 某个字段确实没有内容时，写"无"
- 不要开场白，不要总结
```

这是防止模型编内容的关键。

### 默认模板（固定字段格式）

```
请查看这张图片，按下面的字段输出中文描述，用于文档检索。

每行一个字段，只输出这几行，不要加其他说明：
类型：这是什么（文件类型或场景）
文字：图中可见的关键文字（标题、单位名称、编号、日期、金额、规格等）
画面：画面主要对象与特征（设备、场地、人物、签章等）

要求：
- 只描述你确实看到的内容，不要推测、不要评价、不要补充常识
- 某个字段确实没有内容时，写"无"
- 不要开场白，不要总结
```

### 输出格式：两种，可配

| | 固定字段（默认） | 自然段 |
|---|---|---|
| 检索命中 | **更高**（结构化文本关键词匹配更准） | 一般 |
| 前端展示 | 整齐，信息可扫读 | 一段话 |
| 模型稳定性 | 需要后端校验兜底 | 更稳 |
| 可读性 | 生硬 | 自然 |

**固定字段模式必须做轻量校验**：字段名不在白名单的行丢弃、缺失字段补「无」、
`文字` 字段按配置的上限截断。不让脏输出进 markdown。

## 四、摘要产出与回填

回填在**图片下方**，引用块格式（选引用块是为了切块保护好识别，见第五节）：

```markdown
![](images/image5.jpg)
> 图片说明：
> 类型：房地产权证内页（表格清单）
> 文字：权属人 珠海南方软件园发展有限公司；房屋用途 工业；终止日期 2044-03-17；
>       使用权面积 叁仟陆佰捌拾肆点陆伍平方米
> 画面：左右分栏表格版式，右栏为土地状况，右下角盖有红色圆形公章
```

自然段模式则为：

```markdown
![](images/image5.jpg)
> 图片说明：房地产权证内页，权属人"珠海南方软件园发展有限公司"，房屋用途工业，
> 终止日期 2044-03-17，表格右下角盖有红色圆形公章。
```

**为什么放图片下方**：

1. 符合图注惯例（论文与出版物的 caption 在图下方）
2. 首图不会"串到标题上"——若放上方，"### 11.1 生产场地" 后紧跟摘要，看起来像在描述标题
3. 切块保护做**向后扩展**比向前扩展简单（向前会遇到"上一张图的摘要"的归属歧义）

## 五、切块保护

`chunking/common.py` 的 `find_protected_ranges` 已把「表格 / HTML 表格 / 代码块 /
**图片引用**」列为不可切分区间，但 `_find_image_ranges`（`common.py:273`）保护的
**只有 `![alt](src)` 那一小段**（它原本是为了修一个 bug：引用里的 `!` 被句子感知
切分当分隔符，把 `![](url)` 拆成残废文本）。

**摘要文字不在保护范围内** → 切块边界若落在图与摘要之间，两者会分家。

**改法**：把 `_find_image_ranges` 扩展为「图片引用 + 紧随的一组 `> ` 引用块行」
作为一个区间，一条正则即可识别：

```
!\[[^\]]*\]\([^)]*\)(\n>[^\n]*)+
```

这样无论超长回退还是常规切分，「图 + 摘要」都作为原子整体并入某一块。

## 六、失败与边界

| 场景 | 处理 |
|---|---|
| 没配置模型 | 解析弹窗预检拦截，提示"请联系管理员配置" |
| 配置了但连不上 | 同上；保存配置时的连接测试另行报错 |
| **单张图失败**（超时/格式不支持/被拒答） | **跳过 + 记一笔**（哪些图没摘要成功），不阻塞主流程 |
| 图面积过小（印章类） | 跳过（沿用"面积 < 底图 40%"的判定思路），避免"这是一个红色印章"式废话摘要 |
| 超过张数上限 | 跳过超出部分 + 记录（默认 50 张，可配，可关） |
| 输出格式不符 | 字段白名单过滤 + 缺失补「无」+ 长度截断 |
| 存量文档 | 不自动补摘要，需重新解析 |

**图片摘要不该有否决权**：它是增强功能，一张图解析失败不能导致整篇文档入库失败。

## 八、验收方式

1. **单测** `image_summary`：成功 / 单图失败 / 超限 / 跳过小图 / 输出校验截断
2. **切块回归**：`_find_image_ranges` 改动后跑现有 chunking 测试，并拿真实文档比对
   「图与摘要不分离」
3. **端到端**：拿真实投标文件开启摘要，验证图中文字可被检索
   （例：搜"珠海南方软件园"能召回那张权证图）
