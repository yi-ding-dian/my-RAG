# 表格管道化与渲染原理（HTML 表格 → 管道表格 → 前端渲染）

> 本文档说明知识库中文档表格的完整处理链路：为什么会有"AI 回复显示
> `<table><tr><td>` 看不懂"的问题、三层解决方案（入库前转换 → prompt 约束 →
> 前端渲染）的原理与边界。
> 对应代码：`backend/services/table_normalizer.py`（后端转换）、
> `frontend/src/components/MarkdownTable.tsx`（前端渲染）、
> `backend/services/chat_service.py`（system prompt 约束）。

---

## 一、问题背景与链路分析

MinerU 解析 PDF/docx 时表格输出为 **HTML `<table>` 标签文本**（table_enable 开启时），
例如：

```html
<table><tr><td><p>产业链环节</p></td>...</tr><tr><td rowspan="6"><p>上游算力与基础设施层</p></td>...</tr></table>
```

入库时切块层已有 **HTML 表格原子保护**（`splitter.find_protected_ranges`，
`<table>…</table>` 作为整体归入某块），所以"完整表格入库"没有问题。
问题出在**后续链路**：

```
MinerU 解析 → md 含 HTML <table>（标签冗余占文本一半）
    → 切块保护成块入库 ✅
    ↓
召回：完整 HTML 表格块进上下文（一张 6列×9行 的表 ≈ 5000+ 字符）
    ↓
LLM：复述/总结耗 token 巨大、表格语义被标签噪声干扰 → 易被 max_tokens 截断；
     输出时容易照抄 <table> 标签；（"原样输出"类自定义模板更是要求表格原样保留）
    ↓
前端：纯文本渲染 + 清洗行首符号 —— 用户看到 "<table><tr><td>…" 根本看不懂
```

一句话：**表格在"解析产物里是 HTML 标签、上下文里太大、LLM 输出会照抄、
前端不会渲染"四个环节同时吃亏**。

---

## 二、方案总览：三层递进

| 层 | 位置 | 作用 | 收益 |
|---|---|---|---|
| 1 | 入库前（解析后、切块前） | HTML `<table>` → markdown 管道表格 | token 省 27%+、LLM 可读性高、输出截断概率大降 |
| 2 | system prompt（内置模板） | 要求表格用管道或自然语言，禁输出 HTML 标签 | 止血：LLM 不再照抄标签 |
| 3 | 前端渲染 | 管道表格（+HTML 表格存量兜底）渲染为真实表格 | 用户看到干净表格，半截自动回退 |

---

## 三、第 1 层：入库前 HTML → 管道转换

`backend/services/table_normalizer.py`：`html_tables_to_pipe(text) -> str`，Python
标准库 `html.parser` 实现（**零新增依赖**，离线构建/内网可控）。调用点：
`ingestion_service.py` 解析后、`rewrite_image_refs`（图片引用替换）之后、
落盘之前——转换后落盘/切块/检索共用干净文本。

### 转换规则

| 场景 | 处理 |
|---|---|
| `<th>` / `<td>` | → 管道单元格 `| 内容 |`，单元格内 `|` 转义为 `\|` |
| `rowspan="n"` | 后续 n-1 行**重复填充该值**（信息保真："上游层"跨 6 行每行可见） |
| `colspan="n"` | 行内展开为 n 列重复值（管道语法没有合并单元格） |
| 单元格内 `<p>` 多段 / `<br>` | 空白折叠为单空格（单元格单行化） |
| 单元格内 `<img>` | 保留为 `![alt](src)`（src 已是鉴权代理 URL，原样保留） |
| 未闭合 `<table>` | 转换到文末，不崩溃（与 splitter 同口径） |
| 无 `<tr>` 的空表 | 整体丢弃 |
| 含 `<th>` 的行 | 第一个含 `<th>` 行为表头（纯 td 时首行作表头兜底） |
| 列数不齐 | 按最宽行补空单元格 |
| 表格前后 | 自动补空行，与上下文分段 |

不做的事：`<formula>` 等公式标签原样保留；表内不嵌套 table（MinerU 不产，
嵌套按首个 `</table>` 截断）。

### 实测数据（2026 行业全景报告，含跨页表格）

- 转换后 **HTML 标签数 = 0**，表格全部为管道格式，`rowspan=6` 跨行重复正确；
- 字符数 **13745 vs 存量 HTML 版 20519（省 33%）**；另一文档省 27%；
- 转换后**每张表格仍整体成块**（切块保护区间识别管道表格，与 HTML 一致）。

## 四、第 2 层：system prompt 表格约束

内置模板 `_SYSTEM_PROMPT_TEMPLATE` 第 5 条（`chat_service.py`）：

> 引用内容如含表格，请用 markdown 表格（| 列 | 列 | 形式）或自然语言描述呈现，
> 禁止输出 HTML 标签（<table>、<tr>、<td> 等）。

**边界**：自定义 system_prompt（无占位符模板）覆盖内置规则，第 5 条不生效。
若自定义模板要求"表格原样输出"，由第 1 层（库内已是管道）+ 第 3 层（前端渲染）
闭环兜底——模型照抄的管道表格前端照样渲染成真表格。

---

## 五、第 3 层：前端渲染

`frontend/src/components/MarkdownTable.tsx`（`renderTableBlocks` + `<MarkdownTable>`）：

- **管道表格**：连续 `|` 行且"表头行 + 分隔行齐全"才渲染为 `<table>`；
  流式增量中半个表格（只有表头/无分隔行）**自动回退纯文本原样展示**——
  不存在闪烁的半截表格；
- **HTML `<table>` 块**（存量文档兜底）：浏览器内置 `DOMParser` 解析
  （不执行脚本、只取文本，**无 XSS 面**），rowspan/colspan 展开与后端同一算法；
- 单元格内图片（`![]()`）交给 `MdImages` 渲染；
- 容器 `overflow-x: auto`（超宽表横向滚动），`.md-table` 双主题样式
  （亮/暗，`index.css`）；
- 接入点：`MessageList.renderContent` 中先于 `[n]` 引用标拆分提取表格块，
  表格之外文本走原有管道（引用标 Tooltip / 图片）。

## 六、Excel 公式计算与数字显示(公式引擎)

**背景**:企业报表(财务/汇总/报销)大量使用公式(SUM/AVERAGE 等),WPS 保存的
xlsx **只存公式、不存计算缓存**(openpyxl data_only=True 读不出值)→ 类 Excel 预览
与入库把公式单元格当空白,用户看到"数据缺失"。

**方案**(三层兜底,保证任何情况都不空白、不崩溃):

```
读取单元格值(data_only) → 有缓存值? 用之
    ↓ 无值(疑似公式)
检测(data_only=False 回读) → 是公式?
    ↓ 是
① formulas 引擎重算(纯 Python,SUM/AVERAGE/IF/ROUND/VLOOKUP 等常见函数)
    ↓ 算得出? 用计算值(优先)
    ↓ 算不出
② 显示公式文本(如 =SUM(C3:C16),WPS 双等号归一)= 绝不空白
③ 数值 display 净化:round(8) + 10 位有效截断(数学浮点尾差)
   "230.17999999999998" → "230.18",与 Excel General 观感一致
```

关键设计:

- **触发**:仅"有公式且无缓存"时重算;普通文件零开销;
- **缓存**:`data/spreadsheet_cache/{md5(文件内容)}.json`,首次 ~1.6s,之后秒读
  (内容变化自动失效);
- **数字格式还原**:货币(¥/￥/$,含全角)/千分位/固定小数/百分比/日期按
  Excel number_format 显示,如 ¥374.90;
- **共享**:入库(管道表格)与预览(类 Excel HTML)共用一个计算结果,两边数值一致;
- **兜底**:引擎异常/复杂公式(跨工作簿/宏/数组)→ 显示公式文本,绝不报错。

实现:`backend/services/spreadsheet_formula.py`(引擎+缓存)、
`spreadsheet_xlsx.py` / `spreadsheet_preview.py` 接入、
`spreadsheet_reader.humanize_number`(共用数值净化)。

## 七、边界与已知限制

- **存量已入库文档不回溯**：转换只对新解析生效；存量文档需在文档管理页
  "重新解析"（取消解析后再入库）后生效。前端 HTML 表格渲染仅作显示兜底，
  不改变存量库内内容（token 仍偏大）。
- **MinerU 表格服务地址**：本地/局域网均支持，由配置档案 `mineru.url` 指定；
  服务不可用时降级纯文本解析（无表格识别），管道转换自然跳过。
- 第 4 层（截断提示 + 继续生成）未实现，属后续可选优化——管道化后
  LLM 输出表格 token 大降，截断概率显著降低。
