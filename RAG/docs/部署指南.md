# 部署指南（Docker 生产部署）

> 面向**从零开始的新机器**，命令可直接复制执行。
> 假设：Ubuntu 22.04 / 24.04，有 sudo 的普通用户，服务器 IP 记为 `10.0.0.5`（替换成实际值）。
> 全程在 `~/my-RAG/RAG` 目录执行——compose 文件位置固定，换目录会找不到文件。

## 两种部署方式

| 方式 | 适用 | 入口 |
|---|---|---|
| **一键脚本（推荐）** | 全新机器、标准部署 | `./deploy/deploy-docker.sh` |
| 手动逐步 | 需要理解每一步、或有较多自定义 | 本文第 2-11 节 |

**一键脚本**会自动完成：环境检查 → 生成配置 → 起 MySQL → （可选）MinIO / Milvus →
拉镜像 → 构建 → 启动 → 验证，每一步打印耗时，完整日志落盘；先在脚本顶部改配置
（不改用默认值），运行后展示部署计划，回车才执行。

```bash
./deploy/deploy-docker.sh --dry-run   # 只预览部署计划
./deploy/deploy-docker.sh             # 交互部署（回车确认）
./deploy/deploy-docker.sh --yes       # 跳过确认
```

常用组合（环境变量覆盖脚本内默认值）：

```bash
# 默认：本地存储 + 嵌入式 Chroma + 自带 MySQL
./deploy/deploy-docker.sh

# 启用 MinIO 对象存储 + Milvus 向量库（脚本自动起对应容器）
STORAGE_BACKEND=minio VECTOR_BACKEND=milvus ./deploy/deploy-docker.sh

# 使用已有 MySQL（不新建容器）
INSTALL_MYSQL=no EXTERNAL_MYSQL_HOST=10.0.0.9 EXTERNAL_MYSQL_PORT=3306 \
  ./deploy/deploy-docker.sh
```

> 选 Milvus 时镜像来自 quay.io / Docker Hub，国内网络可能需要预拉取或配置代理；
> 选 MinIO 时脚本自动生成账号密码并在部署报告中展示。

> 脚本只做**全新部署**；检测到已有 `.env.docker` 或容器会提示退出。
> 下面的手动步骤适合理解细节或排查问题时对照使用。

## 1. 部署架构

```
宿主机
├── rag-frontend   容器（nginx）       MY_RAG_HTTP_PORT → 80    静态页面 + /api 反代
├── rag-backend    容器（FastAPI）     8091 → 8091              业务 API + 向量检索
└── my-rag-mysql   容器（MySQL 8）     5455 → 3306              用户/部门/知识库等元数据

数据持久化：
  ~/my-RAG/RAG/data            → /app/data（上传文件、解析结果、向量库、settings.json）
  ~/my-RAG/RAG/docker/volumes  → MySQL / MinIO 数据卷
```

外部 AI 服务（LLM / Embedding / Rerank / MinerU）**不在本编排内**，通过局域网地址接入。

## 2. 前置检查

### 2.1 安装 Docker

```bash
# 官方脚本（国内一般可用）
curl -fsSL https://get.docker.com | sudo sh

# 当前用户加入 docker 组，之后不用每条命令加 sudo
sudo usermod -aG docker $USER
newgrp docker            # 当前终端立即生效；或退出重新登录

# 验证
docker --version && docker compose version
```

预期输出：`Docker version 2x.x` 和 `Docker Compose version v2.x`。

> **注意**：命令是 `docker compose`（空格，Compose v2）。
> 若机器上是 `docker-compose`（带横杠，旧版 v1），先装新版再继续。

### 2.2 配置镜像加速（国内必做）

不配的话拉基础镜像会慢到超时：

```bash
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json > /dev/null <<'EOF'
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://dockerproxy.net"
  ]
}
EOF
sudo systemctl restart docker

# 验证
docker info | grep -A3 "Registry Mirrors"
```

> 加速器会随时间失效。拉镜像卡住时，改用第 7 节的「代理前缀 + tag」办法，不依赖这里的配置。

### 2.3 检查端口、磁盘、防火墙

```bash
# 8091（后端）、5455（MySQL）、前端端口 必须有空位
ss -ltn | grep -E ':(80|8091|5455)\b' || echo "端口都空闲"

# 至少 10GB 可用（镜像约 1.6GB + 构建缓存 + 业务数据）
df -h ~ | tail -1

# 防火墙：若 ufw 是 active 状态，放行前端端口（按实际端口改）
sudo ufw status
sudo ufw allow 8081/tcp
```

## 3. 获取源码

**服务器能访问 GitHub：**

```bash
cd ~
git clone git@github.com:yi-ding-dian/my-RAG.git
cd my-RAG/RAG
```

**服务器访问不了 GitHub**（在有网的电脑上打包后传输）：

```bash
# 有网电脑（仓库根目录）
git archive --format=tar main --prefix=my-RAG/ | gzip > my-rag-src.tar.gz
scp my-rag-src.tar.gz user@10.0.0.5:/tmp/

# 服务器
cd ~ && tar xzf /tmp/my-rag-src.tar.gz
cd my-RAG/RAG
```

> `git archive` 只包含**已提交**内容；未跟踪文件（本地改动、`.env`）不在包内。

验证：

```bash
ls docker/docker-compose.yml docker/docker-compose.infra.yml
```

## 4. 启动 MySQL（项目自带编排，推荐）

MySQL 是**硬前置**：没有它后端启动直接失败，且无 UI 入口补救。

### 4.1 改口令（必做）

`docker/docker-compose.infra.yml` 里是占位符，**原样启动会用字面量 `<your-password>` 当密码**：

```bash
vi docker/docker-compose.infra.yml
```

要改 **3 处**，且保持一致：

```yaml
environment:
  MYSQL_ROOT_PASSWORD: <root口令>      # ①
  MYSQL_PASSWORD:      <业务口令>      # ②
healthcheck:
  test: ["CMD", "mysqladmin", "ping", "-h", "127.0.0.1", "-u", "root", "-p<root口令>"]  # ③
```

### 4.2 启动

```bash
# 只要 MySQL（MinIO 见下方说明）
docker compose -f docker/docker-compose.infra.yml up -d mysql

# 等健康状态（约 30-60 秒）
docker compose -f docker/docker-compose.infra.yml ps
```

预期状态列显示 `Up (healthy)`。

### 4.3 确认自动创建的库和用户

首次启动会自动创建：

| 项 | 值 |
|---|---|
| 数据库 | `my_rag` |
| 用户 | `app_rag`（密码 = 4.1 填的业务口令） |

```bash
docker exec my-rag-mysql mysql -uroot -p<root口令> -e "SHOW DATABASES; SELECT user,host FROM mysql.user;"
```

> **想用自定义库名/用户名**（如 `my_rag_prod` / `app_rag_prod`）时才需要手动建：
> ```sql
> CREATE DATABASE my_rag_prod CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
> CREATE USER 'app_rag_prod'@'%' IDENTIFIED BY '<业务口令>';
> GRANT ALL PRIVILEGES ON my_rag_prod.* TO 'app_rag_prod'@'%';
> FLUSH PRIVILEGES;
> ```
> 用 infra 默认值则跳过。

### 4.4 MinIO（可选）

`STORAGE_BACKEND=local` 时不需要 MinIO，文件直接存 `data/storage`。

**同机部署：**

```bash
docker compose -f docker/docker-compose.infra.yml up -d minio
# 控制台 http://10.0.0.5:9001（账号/密码见 infra 文件）
```

**对象存储单独部署到另一台机器：**

```bash
cd ~/my-RAG/RAG/docker/Minio
vi docker-compose.yml          # 改两个占位符口令（access-key / secret-key）
docker compose up -d
docker compose ps              # 等 healthy
```

> 两种方式**只选一种**（端口都是 9000/9001，同机同时起会冲突）。
> 独立部署后在「系统配置 → 数据存储」里把 endpoint 填成那台机器的 IP。

### 4.5 使用已有 MySQL

跳过本节，跳到第 5 节，在 `.env.docker` 里填那台 MySQL 的地址、端口和账号。

> **注意**：MySQL 若配置了来源 IP 白名单，需放行 Docker 网段
> （`docker network inspect` 查看网关），否则后端启动时建库失败。

## 5. 配置环境变量

```bash
cd ~/my-RAG/RAG
cp docker/.env.docker.example docker/.env.docker
chmod 600 docker/.env.docker          # 含密钥，收紧权限
vi docker/.env.docker
```

**必须修改的字段：**

| 字段 | 填什么 | 说明 |
|---|---|---|
| `JWT_SECRET` | `openssl rand -hex 32` 的输出 | 必填；**少于 16 字符会拒绝启动** |
| `MYSQL_HOST` | `host.docker.internal` | **不能填 127.0.0.1**（那是容器自己） |
| `MYSQL_PORT` | `5455` | infra 映射到宿主机的端口 |
| `MYSQL_USER` | `app_rag` | infra 自动创建的用户 |
| `MYSQL_PASSWORD` | 4.1 填的业务口令 | |
| `MYSQL_DATABASE` | `my_rag` | infra 自动创建的库 |
| `STORAGE_BACKEND` | `local` | 没起 MinIO 就改这里（默认是 `minio`） |
| `MY_RAG_HTTP_PORT` | `8081` | 前端宿主端口；80 空闲可写 80 |

保持默认：`DATA_DIR=/app/data`、`CORS_ORIGINS=`（空，nginx 同源）、`MYSQL_URL=`（空）。

生成 JWT_SECRET：

```bash
openssl rand -hex 32
```

验证（确认没有空值和占位符）：

```bash
grep -vE "JWT_SECRET|PASSWORD" docker/.env.docker
```

## 6. 准备数据目录

```bash
cd ~/my-RAG/RAG
mkdir -p data
sudo chown -R 1000:1000 data
ls -ld data
```

期望看到属主 `1000 1000`。

> **为什么是 1000**：容器内后端以 uid=1000 的 `rag` 用户运行，
> 宿主机目录属主必须对上，否则容器写文件会 Permission denied。

## 7. 拉取基础镜像（国内网络）

先试直连：

```bash
docker pull python:3.12-slim
```

**如果卡住超过 1 分钟**，Ctrl+C，改用代理前缀拉取再重打标准 tag：

```bash
docker pull docker.m.daocloud.io/library/python:3.12-slim
docker tag  docker.m.daocloud.io/library/python:3.12-slim python:3.12-slim

docker pull docker.m.daocloud.io/library/node:22-alpine
docker tag  docker.m.daocloud.io/library/node:22-alpine node:22-alpine

docker pull docker.m.daocloud.io/library/nginx:alpine
docker tag  docker.m.daocloud.io/library/nginx:alpine nginx:alpine
```

> 代理失效就换一个（`dockerproxy.net`、`docker.1ms.run` 等）。
> 判断是否可达：`curl -s -o /dev/null -w "%{http_code}" https://<代理>/v2/`，
> 返回 `200` 或 `401` 都表示可连。

确认四个镜像都在：

```bash
docker images | grep -E "python|node|nginx|mysql"
```

## 8. 构建镜像

```bash
cd ~/my-RAG/RAG

# 国内网络建议带两个源参数；能直连官方源的机器可省略
docker compose -f docker/docker-compose.yml --env-file docker/.env.docker build \
  --build-arg PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple \
  --build-arg NPM_REGISTRY=https://registry.npmmirror.com
```

**⏱ 预计 10-25 分钟，期间长时间没输出是正常的：**

- 后端 `apt-get update && install curl` 在慢网络下可能要 **10 分钟以上**（实测 11.6 分钟）
- 不要以为卡死就 Ctrl+C，中断后下次要重来
- 想留意进度可以另开终端 `docker system df`

成功标志：

```bash
docker images | grep docker-rag
# docker-rag-backend   latest   ...   约 1.5GB
# docker-rag-frontend  latest   ...   约 100MB
```

## 9. 启动服务

```bash
cd ~/my-RAG/RAG
docker compose -f docker/docker-compose.yml --env-file docker/.env.docker up -d

# 查看状态：backend 要变成 healthy
docker compose -f docker/docker-compose.yml ps
```

> **`--env-file` 不能省**：前端端口变量 `${MY_RAG_HTTP_PORT}` 只认 shell 环境变量
> 或 `--env-file`；compose 里的 `env_file:` 只注入容器内部，**不参与** `${}` 插值。
> 不带的话端口会退回默认 80。

## 11. 首次登录后必做

1. **立即修改 admin 密码**（`admin123` 不能留在生产环境）。
2. 进入「系统配置」填写外部服务地址：

   | 服务 | 填写示例 | 说明 |
   |---|---|---|
   | LLM | `http://10.0.0.5:8000/v1` | OpenAI 兼容接口 |
   | Embedding | `http://10.0.0.5:8300/v1` | 必须与已入库向量模型一致 |
   | Rerank | `http://10.0.0.5:8400/v1` | 不配则跳过重排 |
   | MinerU | `http://<MinerU机器IP>:8001` | 文档解析服务 |

   > **容器内不能用 `127.0.0.1`**：那是容器自身。填宿主机局域网 IP，
   > 或使用 compose 已配置的 `host.docker.internal`。
3. 建一个知识库 → 上传文档 → 解析 → 提问，走通完整链路。

## 12. 日常运维

```bash
cd ~/my-RAG/RAG
COMPOSE="docker compose -f docker/docker-compose.yml"

$COMPOSE ps                          # 状态
$COMPOSE logs -f rag-backend         # 后端日志（排查首选）
$COMPOSE logs --tail=100 rag-frontend
$COMPOSE restart rag-backend         # 重启后端
$COMPOSE up -d --build rag-backend   # 重建后端（改代码后）
$COMPOSE down                        # 停止（数据保留）
```

升级到新版本：

```bash
cd ~/my-RAG && git pull
cd RAG
docker compose -f docker/docker-compose.yml --env-file docker/.env.docker up -d --build
```

数据备份（业务关键）：

```bash
# MySQL 全量导出
docker exec my-rag-mysql mysqldump -uroot -p<root口令> --all-databases > backup-$(date +%F).sql

# 文件数据
tar czf my-rag-data-$(date +%F).tar.gz data/
```

## 13. 常见问题排查

### 后端起不来，日志报 `Can't connect to MySQL server`

- `.env.docker` 的 `MYSQL_HOST` 写成了 `127.0.0.1` → 改成 `host.docker.internal`
- MySQL 用户配置了来源 IP 白名单 → 放行 Docker 网段
- 端口写错 → infra 是 **5455**，不是 3306

### `Access denied for user 'app_rag'@...`

用户名/密码与 MySQL 里的不一致。进入容器核对：

```bash
docker exec my-rag-mysql mysql -uroot -p<root口令> -e "SELECT user,host FROM mysql.user;"
```

### 启动报 `JWT_SECRET` 相关错误

值缺失或少于 16 字符：

```bash
openssl rand -hex 32
```

### 前端端口不是预期的（配了 MY_RAG_HTTP_PORT 却不生效）

`up` 命令漏了 `--env-file docker/.env.docker`。

### `port is already allocated`

端口被占用，改 `.env.docker` 的 `MY_RAG_HTTP_PORT` 后重新 `up`：

```bash
ss -ltnp | grep ':80'      # 看是谁占的
```

### 前端 502

后端还没 healthy，等 20 秒再刷新；仍不行看后端日志：

```bash
docker compose -f docker/docker-compose.yml logs --tail=100 rag-backend
```

### 容器写入 data 报 Permission denied

```bash
sudo chown -R 1000:1000 ~/my-RAG/RAG/data
```

### 构建卡在 apt-get / pip / npm 很久

正常现象（慢网络下 10 分钟以上）。确认是否在动：

```bash
docker system df          # BUILD CACHE 是否在增长
```

### 容器日志时间比北京时间早 8 小时

容器默认 UTC。需要统一时在 `.env.docker` 加 `TZ=Asia/Shanghai`（MySQL 容器同理），重启生效。

## 附录：外部服务清单

本项目自身只提供 Web 服务与检索逻辑，以下能力由外部服务提供，地址在「系统配置」页维护：

| 服务 | 是否必需 | 用途 |
|---|---|---|
| MySQL | **必需** | 用户/部门/知识库等元数据 |
| LLM | 必需（问答） | 回答生成、查询改写、切块决策 |
| Embedding | 必需（入库/检索） | 向量化 |
| MinerU | 必需（文档解析） | PDF/Office 解析 |
| Rerank | 可选 | 检索结果重排 |
| MinIO | 可选 | 对象存储（可用 `STORAGE_BACKEND=local` 替代） |
| Gotenberg | 可选 | Office → PDF（需先转 PDF 再交 MinerU 时） |
| RAGAS | 可选 | 独立评估系统，端口 8090 |

> 配错这些地址只影响对应功能，不会导致服务起不来；随时可在 UI 改回。
> 启动硬依赖只有 **MySQL**（以及 `JWT_SECRET`）。
