# Agentic 智能分块原理

> 本文档说明 my-RAG 知识库"Agentic 智能分块"（第六种切块方式）的原理与完整流程。
> 对应代码：`backend/services/agentic_chunker.py`（LLM 切块 + 偏移对齐）、
> `backend/services/ingestion_service.py`（入库链路接入与回退）。

---

## 一、核心思想：让 LLM 读全文，按"语义"切块

```
普通切块：按字符数 / 标题 / 正则 等"规则"切——不理解内容，逻辑段落可能被切断

Agentic 分块：
┌──────────────────────────────────────────────┐
│ 文档全文（≤1 万字）交给 LLM 通读               │
│  LLM 自主判断【完整逻辑段落】并切割             │
│  （观点论证 / 事实陈述 / 操作步骤 / 数据说明）  │
├──────────────────────────────────────────────┤
│ 输出 JSON：块文本 + 类型标签                    │
│  {"chunks":[{"text":"...","label":"论述类"},…]} │
├──────────────────────────────────────────────┤
│ 每块附标签：论述类 / 事实类 / 操作类 / 数据类 / 其他 │
└──────────────────────────────────────────────┘
```

**一句话**：**规则切块"切得整齐但不懂内容"，Agentic 让 LLM 理解文档后按逻辑段落切**——
块内语义完整、块与块之间主题清晰，检索命中时上下文质量更高；块级类型标签还能辅助
下游展示（切块详情显示标签）与按类型定位。

**约束（用户明确）**：仅支持 **≤1 万字** 的文档——超过时 LLM 全量读取 token 成本太高，
前端提示 + 后端校验双保险；与"上下文检索增强 / 知识图谱"两个大模型功能**三选一互斥**。

## 二、完整流程（入库链路）

```
用户选择 method=agentic 触发入库（前端已互斥：自动关闭上下文检索/知识图谱）
  │
  ▼
① 解析文档（与普通入库一致：MinerU / DeepDoc / PlainText 等）
  │
  ▼
② 长度校验（后端 400 双保险）
  │   len(text) > 10000？
  │   ├─ 是 → 任务失败，error="文档超过 1 万字，Agentic 分块成本太高，请换用其他切块方式"
  │   │        （前端轮询到该失败 → 弹提示引导换切块方式）
  │   └─ 否 ↓
  ▼
③ LLM 调用（单次，读全文）
  │   组装消息：system 提示词（切分规则 + 标签白名单 + JSON 输出格式）+ 全文
  │   思考关闭策略 get_thinking_strategy(llm_cfg, thinking_mode)：
  │     ├─ 在线 DeepSeek → extra_body {"thinking":{"type":"disabled"}}（关思考，快且省 token）
  │     └─ 本地 LM Studio Qwen → messages 末尾注入空 <think> 块（跳过思考）
  │   超时 120s；失败/超时/响应非法 → 抛 AgenticChunkError
  ▼
④ 响应解析
  │   直接 JSON → 剥 ```json 围栏 → 剥前后缀说明文字（模型常见输出形态，宽容处理）
  │   块文本逐字拷贝原文校验（提示词要求不改写）；标签白名单外 → 归"其他"
  ▼
⑤ 偏移对齐 align_chunks（核心，见第三节）
  │   每块 LLM 输出文本 → 在原文定位 [char_start, char_end)
  │   对齐失败块 → 丢弃（warning 日志）；全部失败 → 抛 AgenticChunkError
  ▼
⑥ 入库
  │   块文本用【原文切片】重建（保证 text == 原文[char_start:char_end] 偏移契约）
  │   向量化入库；chunks_meta 每块带 label 字段（可选，无标签的块不带）
  │   parser_id=agentic 持久化（重跑沿用）
  ▼
⑦ 失败回退（绝不阻塞入库）
      AgenticChunkError（LLM 失败/超时/对齐全失败）→ 自动回退【按标题切块】
      （warning 日志注明回退原因；文档仍正常入库，无标签）
```

## 三、偏移对齐原理（核心难点）

**为什么需要对齐**：LLM 输出的块文本只是"字符序列"，没有位置信息。入库要求每个块
带 char_start/char_end（相对解析全文的偏移，检索高亮/引用定位/详情展示都依赖它），
且契约要求 `块.text == 全文[char_start:char_end]`。所以必须把 LLM 的每一块文本
重新定位回原文。

**三级定位策略**（`align_chunks`，逐块顺序推进——每块从上一块结束处之后查找，
防止重复内容错位匹配）：

```
对每个块（原文有序查找）：
  ① 精确匹配    → 原文.find(块文本)                    —— LLM 逐字拷贝时一次命中
  ② 折叠空白匹配 → 原文去空白后 find 块去空白文本        —— LLM 改写换行/缩进时命中
                  （原文去空白建立 flat + 偏移映射表，二分定位，O(n) 一次构建）
  ③ 前缀 seed + 滑动窗口 difflib 最长匹配
                  → seed 取块前 N 字符（30/20/10/5 逐级缩短，改写通常在中后部）
                  → 以 seed 命中点为中心开窗口（±块长）
                  → SequenceMatcher 求块与窗口的最长公共子串
                  → 匹配长度 ≥ 块长 50% 才接受（且起点不回头）
                    —— 块被模型改写个别字/输出截断（超 max_tokens）时兜底
```

**失败语义**：
- 单块定位失败 → 丢弃该块（连同标签），warning 日志（`丢弃块#N: …`），不影响其他块；
- **全部失败 → 抛 AgenticChunkError → 入库回退按标题切块**（绝不入库空结果）。

## 四、关键设计点

| 设计 | 原理 |
|---|---|
| **LLM 读全文单次调用** | ≤1 万字约束下全文一次性交给 LLM，全局上下文完整（能判断"完整逻辑段落"的前提） |
| **每块 ≤1500 字**（提示词约束） | 块大小合理，检索粒度精细；LLM 输出总量接近全文，`max_tokens=8192` 给足余量 |
| **块文本逐字拷贝**（提示词要求） | 不改写、不概括，保证对齐可行、检索命中原文可溯源 |
| **偏移契约** | 入库块文本一律用**原文切片重建**（不直接用 LLM 输出），`text == 原文[char_start:char_end]` 恒成立 |
| **标签白名单 + 宽容归一** | 论述类/事实类/操作类/数据类/其他；LLM 输出白名单外标签 → 归"其他"（不丢块） |
| **思考关闭策略复用** | 与图谱抽取/上下文摘要同款 `get_thinking_strategy`：在线 DeepSeek→extra_body 关思考；本地 Qwen→prefill 注入空 `<think>` 块（LM Studio 0.4.x 忽略 extra_body），加速且省 token |
| **解析 LLM 模型可指定** | `parse_llm_model` 指定专用模型（从激活档案查配置覆盖，查不到回退激活模型），对话不受影响 |
| **三选一互斥** | 与上下文检索增强/知识图谱互斥：前端选 agentic 自动关闭并禁用两开关（tooltip 说明）；后端 `resolve_parser_config` 强制关闭（防 API 直调/重跑沿用旧配置组合） |
| **失败回退不阻塞** | LLM 失败/超时/对齐全失败 → 回退按标题切块 + warning 注明原因，入库照常完成 |
| **1 万字硬上限** | 长度校验在解析出文本后、切块前（任务内 ValueError → failed）；前端提交前无法预知文本长度，由后端校验后经 doc.error 传递提示"成本太高换方式" |

## 五、与其他切块方式对比

| 方式 | 块结构 | 特点 |
|---|---|---|
| naive 通用切块 | 等长字符切片 | 简单通用，无结构感知 |
| title 按标题切块 | 每标题一节（支持多种纯文本标题样式） | 章节结构保留，长章节整块检索 |
| regex 正则切块 | 按自定义正则边界切 | 灵活，适合固定格式文档 |
| parent_child 父子分块 | 子块（检索）+ 父块（上下文）双层 | 精准度与上下文完整性兼顾 |
| qa 问答切块 | 问答对整块 | 仅限规范问答格式文档（问:/答:） |
| **agentic 智能分块** | **LLM 按逻辑段落切 + 类型标签** | 语义最完整、块质量最高；成本最高（LLM 读全文），仅 ≤1 万字；与上下文检索增强/知识图谱互斥；LLM 失败自动回退标题切块 |

## 六、成本与容错

| 项 | 说明 |
|---|---|
| **LLM 成本** | 单次调用读全文（≤1 万字）+ 输出全部块文本（接近全文）——输入输出都大，故限定 1 万字上限，超限明确拒绝（"成本太高"） |
| **调用超时** | 120s（读全文 + 输出全部块较重，给足余量；超时 → AgenticChunkError → 回退标题切块） |
| **容错链** | LLM 未配置 / 调用失败 / 超时 / 响应非法 / 空块 / 对齐全失败 → 全部走回退，**绝不阻塞入库** |
| **思考关闭** | 在线模型默认关闭 thinking（disabled），显著降耗时与 token；本地模型注入 prefill 等效关闭 |
