# 上下文检索增强（Contextual Retrieval）原理

> 本文档说明 my-RAG 知识库"上下文检索增强"功能的原理、流程与设计取舍。
> 对应代码：`backend/services/contextual_retriever.py`

---

## 一、核心思想

**问题**：孤立分块缺乏全局背景。例如文档某块只有一句"他放弃了竞选"——纯向量检索不知道"他"是谁、在什么语境下说的，匹配质量差（参考 Anthropic 上下文检索做法）。

**方案**：切块后用 LLM 为每个块生成一段**上下文摘要**，向量化/检索时用 `【上下文】摘要 + 原文` 代替纯原文——让每个块自带"它在这篇文档里是讲什么的"背景。

```
原文块：……他放弃了竞选……
        ↓ LLM 生成摘要（结合前后文）
向量化文本： 【上下文】2024年总统候选人张三在初选辩论后的记者会上宣布放弃竞选
            ……他放弃了竞选……
```

---

## 二、入库流程（切块后处理）

```
文档解析 → 切块完成
   ↓（开关 contextual_retrieval 开启）
逐块调 LLM 生成上下文摘要（enrich_chunks）
  │  每块提示词："用一句话（不超过80字）概括该片段在文档中的
  │  上下文位置与主题"
  │  文档背景 = 文档名 + 全文前 1500 字符（全局上下文，参考 Anthropic 做法）
  ↓
向量化改用  "【上下文】摘要\n原文"     ← 关键
  ↓
入库：chunks_meta.text 保持原样（偏移契约不破坏）
      + context 字段单独存储（摘要）
```

**工程容错**：
- 并发 3（asyncio.Semaphore）；单调用超时 15s
- **失败/超时/空摘要 → 该块跳过**（warning 日志），**绝不阻塞入库**
- LLM 未配置 → 跳过整个摘要生成，入库正常

---

## 三、摘要生成细节

| 项 | 设计 |
|---|---|
| 输入 | 块文本（截断 1000 字）+ 文档背景（文档名 + 全文前 1500 字符） |
| 输出约束 | 一句话 ≤80 字（超长兜底截断） |
| 模型 | 解析配置"解析 LLM 模型"（parse_llm_model），未指定用激活对话模型 |
| 思考模式 | 跟随配置（DeepSeek extra_body 关闭思考 / 本地 Qwen prefill），默认关闭思考加速 |
| max_tokens | 1024（**历史教训**：推理模型 thinking 会吃光小 max_tokens 导致摘要恒空，200→1024 修复，实测 0.84s/块） |

---

## 四、数据模型与偏移契约

```
chunks_meta 条目：
{
  "text": "原文块文本（原样，char 偏移契约不破坏）",
  "char_start": 123, "char_end": 140,
  "context": "【上下文】2024年总统候选人张三……宣布放弃竞选"   ← 单独存储
}
```

- **text 保持原样**：切块详情/引用溯源/原文定位全部依赖偏移契约，摘要不污染原文
- **向量化用拼接文本**：`context + "\n" + text`（检索匹配发生在拼接文本空间）

---

## 五、检索时

```
用户提问 → 向量化
  ↓
在 "【上下文】摘要\n原文" 的向量空间检索（摘要补上了块缺失的语境）
  ↓
命中片段 → 返回/展示用原文 text（context 只用于匹配）
```

**效果**：短块、前后文依赖强的文档（对话记录、合同条款、新闻报道）检索命中率显著提升。

---

## 六、开关与互斥

- 解析配置"大模型处理"区开关（默认关，开启提示 token 费用）
- **互斥**：与 Agentic 智能分块互斥（都是大模型参与，三选一改为二选一：上下文检索 与 Agentic 不能同时开；知识图谱可叠加）

---

## 七、成本与适用场景

| 项 | 说明 |
|---|---|
| 成本 | 每块一次 LLM 调用（一份 50 块文档 ≈ 50 次小调用，关闭思考后约 0.8s/块） |
| 适用 | 短块 + 前后文依赖强的文档（对话/条款/新闻） |
| 不适用 | 块本身语义完整的长段落文档（增益不明显，白花钱） |

**取舍**：检索质量提升 vs 入库变慢 + token 费用——按文档类型决定是否开启。
