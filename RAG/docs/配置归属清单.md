# my-RAG 配置归属清单

> 目的：明确每个配置项**唯一**应该放在哪里，消除"两处都能配、改哪都不对"的混乱。
> 盘点依据：`.env.example`（36 项）、`backend/services/settings/schema.py` 的
> `SECTION_SCHEMA`（18 个配置段）、`data/settings.json` 实际值。2026-09-28。

---

## 一、判断原则

按优先级依次判断，**命中即停**：

| # | 判据 | 结论 | 理由 |
|---|---|---|---|
| 1 | **配错会导致进程起不来？** | **必须外部**（`.env`） | 启动依赖。配错 + 重启 = 起不来 = 进不了 UI 改回来（自锁） |
| 2 | **开发/测试/生产要用不同的值？** | **必须外部** | 环境相关，随部署走 |
| 3 | **是密钥？** | **必须外部** | 不进 UI、不进 DB、不进日志，缩小泄露面 |
| 4 | 以上都不是 | **可以内部**（配置档案/DB） | 业务参数：要能热调、要留痕、跨环境一致 |

**常见反例**（不该放外部，放了只会让部署时漏配）：
业务阈值、提示词模板、功能开关、检索 top_k —— 它们跟环境无关。

## 二、归属总表

### 类别 1：必须外部（`.env` / `.env.docker`）

| 配置项 | 现状 | 说明 |
|---|---|---|
| `JWT_SECRET` | ✅ 已在 `.env` | 启动时强度校验，不合格**拒绝启动**（`main.py:86`） |
| `HOST` / `PORT` | ✅ 已在 `.env` | 进程监听地址 |
| `DATA_DIR` | ⚠️ 仅代码默认 | 数据根目录，决定所有路径常量（uploads/parsed/chat…） |
| `CORS_ORIGINS` | ✅ 已在 `.env` | 前端域名，随环境变 |
| `MYSQL_HOST/PORT/USER/PASSWORD/DATABASE` | ⚠️ 已在 `.env.example` 但被档案覆盖 | **启动依赖**，配错起不来 |
| `MYSQL_URL` | ⚠️ 同上 | 仅离线测试用（sqlite），生产留空 |
| `MINIO_ENDPOINT/ACCESS_KEY/SECRET_KEY/BUCKET` | ⚠️ 同上 | 启动时 `ensure_bucket()` |
| `STORAGE_BACKEND` | ⚠️ 同上 | 决定存储实现（minio/local） |
| `VECTOR_BACKEND` / `MILVUS_URI` | ⚠️ 已在 `.env.example` 但档案也有 | 决定向量库实现，属启动依赖 |
| `RAGAS_BASE_URL` | ✅ 已在 `.env` | 外部评估服务地址 |

| `chunking.*` | ✅ 档案 | 切块大小 / 重叠 / 标题模型 |

### 类别 3：⚠️ 当前"两处都能配"，需要指定唯一来源

**这是混乱的根源**——同一项在 `.env` 和配置档案里各有一份，实际生效的是档案（`profile > .env`），
但很多人会去改 `.env`，改完不生效。

| 配置项 | `.env` | 档案 | 建议唯一来源 |
|---|---|---|---|
| LLM `base_url` | `LLM_BASE_URL` | `llm.models[].base_url` | **档案**（需多模型切换） |
| LLM `api_key` | `LLM_API_KEY` | `llm.models[].api_key` | **`.env`**（密钥不外露）※见下 |
| LLM `model` / `temperature` / `max_tokens` | ✅ | ✅ | **档案** |
| Embedding `base_url` / `model` | ✅ | ✅ | **档案** |
| Embedding `api_key` | ✅ | ✅ | **`.env`** |
| `MINERU_API_URL` | ✅ | `mineru.url` | **`.env`**（服务发现） |
| `MINERU_TIMEOUT` | ✅ | ✅ | **档案** |
| DeepDoc `base_url` / `email` / `password` | ✅ | ✅ | **`.env`** |
| `RETRIEVAL_TOP_K` | ✅ | `retrieval.top_k` | **档案**（页面上要实时调） |
| `CHUNK_SIZE` / `CHUNK_OVERLAP` | ✅ | `chunking.*` | **档案** |
| `CHAT_HISTORY_ROUNDS` | ✅ | `chat.history_rounds` | **档案** |

> ※ 密钥的取舍：项目现状是"密钥也在档案里（UI 可配、脱敏显示、600 权限落盘）"，
> 对自用/小团队可接受；**若要多副本或对外**，密钥应统一收进 `.env`，
> 档案里只留非敏感字段（此时 `llm.models[].api_key` 只作可选覆盖）。

### 类别 4：应该在代码里（不做成配置）

| 项 | 位置 | 理由 |
|---|---|---|
| `_SPLIT_MAX_TOKENS` / `_MAX_SUB_QUERIES` / `_TIMEOUT` | `query_rewriter.py:203-215` | 算法参数，改动即改行为，应走代码 review |
| 各类启发式词表（`_COMPLEX_INDICATORS` 等） | 同上 | 同上 |
| 图谱扩展跳数、rerank 校验阈值 | 各 service | 同上 |

**判据**：改它需要重新理解/验证算法 → 代码；改它只是调效果 → 配置。

## 三、现状的 4 个问题

| # | 问题 | 影响 | 严重度 |
|---|---|---|---|
| 1 | **类别 3 的双重定义** | 改 `.env` 不生效（被档案覆盖），排查成本高 | 🟡 |
| 2 | **数据库/MinIO 可在 UI 配** | 配错 + 重启 = 启动失败 = 进不了 UI（自锁） | 🔴 |
| 3 | **全局配置在文件，部门配置在库** | 多副本下全局配置分裂（部门配置反而正常共享） | 🟡 |
| 4 | **`settings.json` 不在数据库备份里** | 换机器只恢复数据库 → 全局配置静默回退默认值 | 🔴 |

### 配置优先级链（当前实际）

```
部门配置（DB: departments.chat_config）      ← 最高
  > 全局配置档案（data/settings.json）
    > .env（出厂默认）
      > config.py 代码默认值                  ← 最低
```

## 四、迁移建议（按性价比排序）

| 优先级 | 动作 | 解决的 |
|---|---|---|
| **1** | 加 `settings.json` 到备份清单（和 `data/` 一起打包，或纳入部署脚本） | 问题 4 |
| **2** | `main.py` 的 `init_db()` 包 try/except：连不上时**降级 SQLite 启动**并告警 | 问题 2（自锁） |
| **3** | 类别 3 的每项，在文档/`.env.example` 注释里标注**唯一来源**，消除误改 | 问题 1 |
| **4** | 全局配置档案落库（新 `settings` 表）+ 启动优先读库、失败回落文件 | 问题 3 |
| 5 | 密钥收进 `.env`，档案只留非敏感字段 | 安全 |

**注意第 4 条的鸡生蛋**：数据库连接配置**不能**存在数据库里，否则连不上就没法读配置。
所以是"**启动依赖留 `.env`，其余配置落库**"的分层，而不是全都落库。

---

## 五、给新部署者的最短检查清单

部署到新机器 / 新服务器时，按顺序确认：

1. `cp .env.example .env`（或 `docker/.env.docker`），填 `JWT_SECRET`、`DATA_DIR`
2. 填 `MYSQL_*`（**启动依赖，配错起不来**）；其余服务地址进 UI 配
3. 启动服务，进 UI → 系统配置，填 LLM / Embedding 地址与密钥、检索参数
4. **备份时记得 `data/settings.json` 要跟着数据库一起走**

## 六、实际落地状态（2026-09-28）

本清单的**判定标准是"配错还能不能进 UI 改回来"**，据此完成了一轮收敛：

| 项 | 状态 |
|---|---|
| `docker/.env.docker` | **36 项 → 11 项**，只留：`JWT_SECRET` / `DATA_DIR` / `CORS_ORIGINS` / `MYSQL_*` / `STORAGE_BACKEND` / `RAGAS_BASE_URL` |
| 数据库（mysql 段） | `apply_to_config=False` —— 档案里配了也**不写入运行时**，只认 `.env`；前端已隐藏该面板 |
| MinIO | **归入 UI**（判定：`ensure_bucket()` 失败只告警、不阻塞启动，配错可从 UI 改回） |
| 其余（LLM / Embedding / MinerU / DeepDoc / 检索 / 切块 / 向量存储…） | 归入 UI |
| 开发机 `.env` | 用 `MYSQL_URL` 指向 sqlite（保持现有数据）；迁好库后删掉该行即切 MySQL |

**两个容易漏的**：`STORAGE_BACKEND` 与 `RAGAS_BASE_URL` **没有对应的 UI 配置段**
（见 `SECTION_SCHEMA` 的 17 个段），删了就再也配不了，**必须留在 `.env`**。

**判据的边界**：MinIO 与 MySQL 是同类服务，但 MinIO 配错只降级、MySQL 配错起不来，
所以一个归 UI、一个留 `.env`——分类不看"服务是什么"，只看"配错后还能不能救回来"。
