# i18n 与移动端适配评估(建议后置)

> 结论先行:**建议后置**。两项均为"大面积改动但有明确边界"的工程,投入产出比远低于
> 当前版本的 P0/P1 修复;若要走,按以下评估分阶段实施。

## 一、i18n 国际化

**现状**:全站中文硬编码(页面/组件/错误提示/弹层约 400+ 处),`main.tsx` 已固定
`zhCN` 的 antd locale。

**方案(推荐 i18next / react-i18next)**:
1. 引入 `i18next` + `react-i18next`,资源文件 `locales/{zh-CN,en-US}.json`;
2. **分批迁移**(不一次性):按页面——先 Chat/登录(已登录用户高频),再管理页;
   组件内 `<T>`/`t()` 替换,antd 缺省文案走 `ConfigProvider locale` 切换;
3. 语言切换入口放 Profile 页(与主题切换并列)。

**成本估算**:① 依赖+脚手架(0.5d)② 分页迁移(每页 0.5~1d,共 6 页)③
服务端返回的**中文文案**(错误提示/审计名等)需同步出字典或保持中文并映射(0.5d)。

**风险**:迁移期 UI 回归面大;服务端错误文案国际化要动后端(契约级)。故**后置**。

## 二、移动端适配

**现状**:桌面优先布局(220px 固定侧栏 + 表格列表),无断点/响应式;AntD 组件
基础可降级,但业务布局(SideMenu/表格/弹窗大宽自适应)未做。

**方案**:
1. 先做**可用级**:侧栏折叠(已支持 AppModal 视口钳制等)、表格横向滚动、
   关键页面(聊天/Chat/文档)在 ≤768px 下改为单列;
2. 再做**完善级**:路由按设备加载移动端专用布局(工作量 +)。

**成本**:可用级约 2~3d(布局/断点/交互验证);完善级另 +2d。

**建议**:若客户明确要"手机/平板查阅",做**可用级**即可(查询/问答为主,不上管理端);
否则后置。

## 三、一阶段建议(如果后面要做的顺序)

1. ErrorBoundary(✅ 已完成,本批)——防白屏的最优性价比;
2. 移动端"可用级"(如客户要求);
3. i18n(有出海/外资客户时再推动)。
